# Paradigm common guidance

Load the applicable reference documents before working:

- [Paradigm Good Coding Practices](references/good-coding-practices.md) for handwritten application and framework code, generated-code boundaries, validation ownership, repository SQL, security, dependencies, and operability.
- [Paradigm Database Practices](references/database-practices.md) for SQL Server and PostgreSQL database source, schema ownership, routines, seed data, lifecycle, deployment, secrets, and baselines.
- [Paradigm Solution Layout](references/solution-layout.md) for canonical solution structure, responsibility folders, mixed application/database solutions, and review invariants.
- [Database-first Models and Contracts](references/database-first-models.md) for EF Core Power Tools output, Domain entities/views, and analyzer-generated interfaces during application setup or data-backed feature work.

Apply the relevant guidance to the task and preserve the centralized policy when updating task-specific skills or tooling. Do not copy these reference documents into another skill.

Database-first Domain entities and database views MUST be generated by EF Core Power Tools using the reviewed T4 templates. Never create their scaffold files manually, through a handwritten script, or as temporary substitutes. Follow the mandatory generation and prerequisite rules in [Database-first Models and Contracts](references/database-first-models.md).

Domain classes unrelated to database elements may be created manually, including value objects, policies, calculations, and other non-persistence models. The EFPT requirement applies to database-first scaffold types, not every class in Domain; do not invent database objects or require `EntityBase` merely to create an unrelated Domain class.
